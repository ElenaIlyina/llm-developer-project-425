# Тикеты и история — шаг 5

## Что развёрнуто

- YDB `help-desk-db`: таблицы `tickets` и `messages`.
- Cloud Function `ydb-tickets`: `d4ek6uo5hmdsbhdb631t`.
- Приватный MCP-шлюз `ydb-tickets-mcp`: `db8fj6b05t8rq2h9k4cv`.
- `email-poller`: версия `d4eitbugrpmno2nbtk5h`, таймер возобновлён.
- Инструменты: `create-ticket` и `list-my-tickets`.
- Пароли и параметры YDB подключены из Lockbox. URL MCP — обычная переменная `MCP_SERVER_URL`.

## Структура и поведение

`src/helpdesk_common.py` содержит параметризованные YQL-запросы и общее маскирование.
`src/ydb_tickets/index.py` принимает прямой JSON, HTTP body (включая base64)
или аргументы MCP без обёртки. При отсутствии action наличие text/category
означает create-ticket; один user_id — list-my-tickets.

Перед вызовом модели поллер читает последние 10 реплик пользователя и сохраняет
текущее письмо. Затем передаёт историю и письмо в Responses API, подключая MCP
с `require_approval: never`. После ответа сохраняет модель из конфигурации,
реальные usage.input_tokens/output_tokens и замер latency_ms. ticket_id берётся
только из результата create-ticket и записывается обеим репликам цикла.

Приоритет отдан основным требованиям step5: история читается из YDB.
Противоречащая им подсказка про отсутствие чтения не применяется.
Идентификаторы сообщений детерминированы по ящику, UIDVALIDITY и UID письма.
Роль agent из YDB преобразуется в assistant для API.

Email, российские телефоны и явно обозначенные пароли/токены в тексте маскируются
перед хранением и передачей модели. user_id остаётся адресом для связи записей.
Это базовые регулярные выражения, а не полная система обнаружения PII.
В логах — имена MCP-действий, количество и роли реплик, токены и время;
полное содержимое писем и секреты не выводятся.

## Воспроизведение

```bash
source .venv/bin/activate
pip install -r src/ydb_tickets/requirements.txt
python -m unittest discover -s tests -v
```

Для начальной схемы задайте YDB_ENDPOINT/YDB_DATABASE только в окружении текущего
процесса из Lockbox, YC_IAM_TOKEN — через `yc iam create-token`. Выполните:

```bash
python scripts/init_schema.py src/ydb_tickets/schema.sql
```

Скрипт создаёт отсутствующие таблицы, сохраняет существующие и не делает DROP.
Изменения структуры уже существующей таблицы требуют отдельной миграции.

Создайте Cloud Function один раз, затем загрузите конфигурацию:

```bash
yc serverless function create --name ydb-tickets
set -a
source .env
set +a
bash scripts/deploy-ydb-tickets.sh
```

Для другого каталога замените оба function_id в `src/ydb_tickets/mcp-tools.yaml`
на ID созданной функции. input_json_schema должен оставаться JSON-строкой.

```bash
SA_ID=$(yc iam service-account get --name ai-studio-sa --format json | jq -r .id)
yc serverless mcp-gateway create \
  --name ydb-tickets-mcp \
  --service-account-id "$SA_ID" \
  --tools-file src/ydb_tickets/mcp-tools.yaml
```

Запишите base_domain из вывода со суффиксом /sse в MCP_SERVER_URL в локальном .env.
На время обновления поллера приостановите таймер:

```bash
yc serverless trigger pause email-poller-trigger
set -a
source .env
set +a
bash scripts/deploy-email-poller.sh
yc serverless trigger resume email-poller-trigger
```

Обновлённый промпт упаковывается в функцию из `prompts/help-desk-system.md`.
UI-агент не участвует в запросе; его инструкции не обновляются автоматически.

## Проверки

Локально проходят 11 тестов: MIME, ошибки писем, MCP-контракты, HTTP,
маскирование, перенос истории, телеметрия и связь двух реплик с тикетом.
Облачная функция проверена прямым invoke; создание и просмотр тикетов — через
реальный Responses API и приватный MCP от имени ai-studio-sa.

Сквозная проверка на искусственном пользователе подтвердила:
создание и просмотр заявок, 4 записи messages, 2 связанные с новым тикетом реплики,
ненулевые usage и latency. Отправка SMTP в этой проверке заменена заглушкой;
искусственные записи удалены. Почтовый приёмочный тест шага 5 пройден 2026-11-03: пользователь получил
номер заявки, затем список своих заявок в ответ на повторное письмо.
Тикет `3903c8f8-c727-4711-9ffa-84d79b9b8bd8` найден в YDB:
категория bug, статус open. Сохранены 4 реплики двух циклов; первые две
связаны с тикетом. Телеметрия ответов: 570/82 токена и 5323 мс,
затем 719/117 токенов и 4026 мс.

Отправьте с личного ящика:

1. «Создай тикет категория bug текст: не работает принтер в переговорной».
2. После получения номера ответьте: «Покажи мои заявки».

Проверьте наличие тикета, двух реплик первого цикла с одинаковым ticket_id,
телеметрии ответа и истории во втором запросе. Если письмо попало в спам,
перенесите его во входящие и оставьте непрочитанным.

## Границы учебного MVP

Флаг Seen не гарантирует отсутствие дублей при сбое между побочными эффектами.
При ошибке обработки письмо помечается прочитанным по условию шага 4.
Адрес берётся из From и передаётся модели доверенной инструкцией; это не проверка
подлинности отправителя и не серверная изоляция пользователей MCP.
Для production нужны проверенная идентичность и проверка доступа в инструменте.
RAG пока не подключён.
