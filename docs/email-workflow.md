# Почтовый канал — шаг 4

Этот документ описывает базовую проверку канала. Текущая версия дополнена
MCP и историей: [шаг 5](tickets-and-history.md).

## Подготовка ящика

Используйте отдельный ящик Help Desk. В настройках Яндекс Почты включите доступ
по IMAP и использование паролей приложений. Создайте пароль приложения «Почта»
в Яндекс ID и сохраните его через консоль Lockbox: секрет `email-credentials`,
ключ `password`. Пароль в репозиторий и чат не переносите.

Запишите в локальный `.env` адрес и идентификаторы из Lockbox:

```dotenv
HELPDESK_MAILBOX=
EMAIL_CREDENTIALS_SECRET_ID=
EMAIL_CREDENTIALS_SECRET_VERSION_ID=
```

## Проверки и деплой

Из корня рабочего репозитория:

```bash
python3.12 -m unittest discover -s tests -v
yc serverless function list
# Выполнить один раз, если email-poller отсутствует:
yc serverless function create --name email-poller
set -a
source .env
set +a
bash scripts/deploy-email-poller.sh
```

Скрипт упаковывает функцию и системный промпт в ZIP. Начиная с шага 5 архив также содержит YDB SDK в requirements.txt.
IAM-токен поступает через metadata service от назначенного функции ai-studio-sa.
Модель и промпт передаются непосредственно в Responses API
(`https://ai.api.cloud.yandex.net/v1/responses`).
`AI_STUDIO_AGENT_ID` сохраняет ссылку на UI-агента, но не используется как prompt ID:
ID runtime-агента и сохранённой конфигурации имеют разное назначение.

## Ручная проверка и таймер

Вызов ниже обрабатывает настоящие непрочитанные письма и отправляет ответы.
Отправьте с другого ящика письмо с темой «Тест» и текстом «привет», затем:

```bash
yc serverless function invoke email-poller
```

Ожидается `processed: 1`, ответ с темой `Re: Тест` и прочитанное исходное письмо.
В логах: `GOT_UNSEEN`, `MSG uid=…`, `AGENT_OK`, `SEND_OK`.
Тексты, адреса и темы писем не логируются.

После успешной ручной проверки создайте таймер один раз:

```bash
SA_ID=$(yc iam service-account get --name ai-studio-sa --format json | jq -r .id)
yc serverless trigger create timer \
  --name email-poller-trigger \
  --cron-expression "0/1 * * * ? *" \
  --invoke-function-name email-poller \
  --invoke-function-tag '$latest' \
  --invoke-function-service-account-id "$SA_ID"
```

Не запускайте ручную обработку одновременно с таймером.

## Поведение MVP

За запуск обрабатывается не более пяти писем; новые обработки прекращаются после
45 секунд. Остальные письма остаются для следующего запуска.
Читаются plain text и HTML; автоматические рассылки и собственные письма пропускаются.
По требованию задания письма с ошибками тоже помечаются прочитанными:
их нужно разбирать вручную. Флаг Seen не обеспечивает строго однократную отправку
при аварии между SMTP и IMAP или параллельных запусках.

### Диагностика доставки

Если ответа нет, проверьте «Спам» в ящике Help Desk: поллер читает только INBOX.
Проверка 2026-11-03: письмо «Проверка таймера» обнаружено в Spam, поэтому
не попадало в выборку поллера. Перенесите тестовое письмо во входящие кнопкой
«Не спам» и оставьте его непрочитанным.
При диагностике также наблюдался единичный обрыв IMAP на SELECT; повторный
вызов завершился успешно. Таймер после диагностики возобновлён.
