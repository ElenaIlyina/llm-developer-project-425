# Почтовый канал

Первое развёртывание описано в [setup.md](setup.md). До поллера должны быть готовы
схема YDB, функция тикетов, приватный MCP и индекс SEARCH_INDEX_ID.
Пароль приложения почты берётся из Lockbox, IAM — из metadata service.

## Обработка

Таймер каждую минуту вызывает email-poller. Функция читает до пяти UNSEEN-писем;
новое письмо не начинает обрабатываться после 20 секунд от старта функции.
MIME поддерживает plain text и HTML. Цитаты Яндекс Почты, Gmail, Outlook,
blockquote и gmail_quote отделяются до определения намерения, защиты и модели.
Обрабатывается новый текст до цитаты; ответы внутри цитаты не поддерживаются.
Короткая благодарность («Спасибо, помогло!») получает фиксированный вежливый
ответ без классификатора, поиска и MCP. Любая дополнительная нецитированная
просьба выводит письмо из этого узкого маршрута.
Автоматические сообщения, рассылки и собственная почта пропускаются.

Regex и классификатор проверяют обращение до вызова агента. Для короткого
согласия проверяется исходная просьба перед предложением заявки. История
сохраняется в YDB и используется в JSON conversation_history для тикетных
операций. Поиск по базе выполняется изолированно от старых ответов, с единственным
инструментом file_search.
Модель предлагает аргументы create-ticket, а поллер выполняет только первое
прошедшее проверку предложение через MCP. user_id и request_id задаёт код.

Успех берётся из результата инструмента; обе реплики связываются с тикетом.
Доставка ответа — SMTP. Необработанные ошибки фиксируются без содержимого писем.
По условию задания даже ошибочное письмо помечается прочитанным. Уведомление
отправителя о техническом сбое пока не реализовано; SMTP не имеет гарантии exactly-once.

## Обновление

```bash
set -a
source .env
set +a
yc serverless trigger pause email-poller-trigger
bash scripts/deploy-email-poller.sh
```

После успешного деплоя и проверки включите таймер:

```bash
yc serverless trigger resume email-poller-trigger
yc serverless trigger get email-poller-trigger
```

Не запускайте ручную обработку одновременно с таймером. При отсутствующем ответе
проверьте Спам и входящие обоих ящиков. Обращение должно оставаться непрочитанным
во Входящих Help Desk. Ссылка UI-агента хранится отдельно: поллер использует
промпт из репозитория, а не сохранённую конфигурацию runtime-агента.
