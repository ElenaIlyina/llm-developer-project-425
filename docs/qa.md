# Шаг 9: QA, токены и трейсы

## Автоматическая облачная проверка

Запускайте из корня репозитория в активном `.venv`, с настроенным `yc` и `.env`:

```bash
python scripts/check_qa_flow.py
python scripts/qa_report.py
```

Первая команда выполняет два реальных цикла поллера: вопрос про принтер и согласие
на bug-тикет. SMTP подменён: писем не будет. Используется случайный тестовый
пользователь; его записи удаляются после проверки. Нужны права на модель, MCP,
YDB, чтение Lockbox и impersonation сервисного аккаунта.

В `docs/evidence/qa-live.json` сохраняются обезличенные `output[]` Responses API,
исходный `usage`, метрики соответствующих строк YDB и результаты точного сравнения.
Проверяются RAG-источник printer.md, вызов MCP create-ticket, четыре реплики и
связь двух реплик создания с ticket_id. Это проверка API/MCP/YDB, почтовый транспорт
проверяется отдельно. Ошибка или отсутствие usage не заменяются нулями.

Вторая команда экспортирует последние 500 messages и до 20 tickets одного
пользователя (`OPERATOR_EMAIL`, либо `--user-id`). Тексты маскируются, user_id
исключён. Файл `qa-token-report.json` содержит дамп, сумму токенов основных ответов
и расчёт месячного сценария. Исторические значения без исходного API-ответа
не считаются проверенными на точное совпадение. Ответы guardrail с нулевыми
метриками исключены из генерации; классификатор оплачивается отдельно.

## Сквозная почтовая проверка

1. Отправьте новое письмо «У меня сломался принтер, что делать?».
2. Дождитесь ответа с источником printer.md. Сделайте скрин обращения и ответа.
3. Ответьте «Не помогло, создай тикет категории bug». Сохраните ответ с ticket_id.
4. Проверьте совпадение ID через функцию:

```bash
yc serverless function invoke ydb-tickets \
  --data '{"action":"list-my-tickets","user_id":"<ваш-email>"}'
```

Приложите скрин письма и результат чтения YDB/отчёт. На скринах скрывайте личные
данные, баланс и секреты. Файлы qa-live.json/qa-token-report.json появляются
только после запуска: подготовка скриптов сама по себе не подтверждает QA.

## Негативные сценарии и наблюдаемость

- Injection: реальный классификатор и прямая блокировка инструмента подтверждены
  в guardrail-checks.json и guardrail-injection.json.
- Неизвестный вопрос: ответ «не знаю», согласие и создание docs-тикета подтверждены
  почтовыми скринами RAG.
- PII: маски в messages и tickets подтверждены pii-storage-check.json.
- Недоступность YDB: полное облачное отключение ещё не проверено. Не меняйте права
  рабочего поллера ради теста; нужен изолированный ресурс. Ошибка workflow доступна
  в error.message; точный HTTP-код сбоя CF зависит от способа вызова.
- Cloud Logging недоступен из-за ограниченного режима платформы. Сохранено сообщение
  об ограничении; облачные логи на PII не проверены. Для inline Responses используются
  реальные output[] в qa-live.json; для workflow — сохранённая история выполнения.

## Стоимость сценария

Тарифы зафиксированы на 06.11.2026 в `config/pricing-2026-11-06.json`, включая ссылки
на официальные источники. `yandexgpt/latest` соответствует Pro 5: 1,20 ₽ за 1000
входящих и за 1000 выходящих токенов. File search — 300 ₽ за 1000 вызовов;
классификатор Lite — 0,1525 ₽ за каждую начатую тысячу токенов запроса.

Индекс округляется до целого GiB: сценарий одного GiB на 30 дней — 318 ₽.
Три активные версии Lockbox на 30 дней — 59,184 ₽. Эти расходы сохраняются даже
при небольшом числе обращений. Скрипт добавляет генерацию по измеренной выборке,
поиск, классификатор и функции для 300 сообщений/месяц; число меняется флагом
`--monthly-messages`. Длительности функций заданы как допущения, не измерения.

Расчёт показывает два случая: бесплатные лимиты функций доступны либо уже
израсходованы. Это частичный бюджет до грантов, а не сумма счёта: отдельно нужны
YDB, чтение Lockbox, сеть, логи, токены дайджеста, индексация и повторы. Фактические
затраты сверяются с детализацией Billing. Состав и исключения сохранены в отчёте.

## Итоговые показатели

Реальный экспорт qa-token-report.json содержит 12 реплик, включая 6 ответов модели:
6847 входящих и 499 выходящих токенов, средняя задержка 4088 мс.
Для 300 обращений в 30 дней учтённая часть бюджета — 965,13–986,72 ₽
в зависимости от доступности бесплатных лимитов функций.

В ответах Yandex total_tokens включает отдельные input_tokens_details.tool_tokens.
Столбцы YDB хранят именно input_tokens/output_tokens; исторические токены
инструментов из них восстановить нельзя, они исключены из оценки.

История передаётся как недоверенный conversation_history внутри JSON. Создание
ограничено явной просьбой или согласием; подтверждение формируется кодом из
результата MCP. Вызовы инструментов и источники проверяются программно.
