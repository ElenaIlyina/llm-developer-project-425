# База знаний и RAG

## Поисковый маршрут

Поллер использует один индекс SEARCH_INDEX_ID, max_num_results=5 и
RAG_SCORE_THRESHOLD (по умолчанию 0.35). Порог настраивается; универсальная
калибровка релевантности не заявляется.

Поиск получает текущее обращение и только file_search. Старые ответы агента
и MCP исключены из этого маршрута. Для ссылочного уточнения допускается
предыдущий пользовательский вопрос; полная история остаётся в маршрутах тикетов.

Ответ строится по найденным фрагментам. Код добавляет ссылку, только если имя
документа присутствует в file_citation, явно названо строкой «Документ: имя-файла.md»
и есть в src/knowledge_sources.json. Неизвестные имена и просто найденные,
но не использованные документы не становятся источниками ответа.

Перед публикацией инструкции отдельный вызов YandexGPT проверяет соответствие
вопроса, ответа и реально найденных фрагментов. Проверяющая модель возвращает
решение и цитату; каждое предложение цитаты сверяется с исходными фрагментами.
Инструкция «VPN не подключается» не подтверждает ответ на вопрос о YouTube через VPN.
Неподтверждённая тема даёт «не знаю», сбой проверки — техническое сообщение.
Проверка вероятностная и не гарантирует отсутствие всех смысловых ошибок.

При отсутствии информации агент говорит «не знаю» и предлагает тикет без
автоматического создания. Ошибка/отсутствие поиска отличается от пустой выдачи:
неподтверждённая инструкция не выдаётся как ответ по базе. Благодарность
обрабатывается отдельно, без модели и поиска.
Если подтверждённого источника нет, текст ответа задаёт код: фраза «не знаю»
в черновике модели не позволяет опубликовать следующие за ней инструкции.

## Корпус

knowledge-base содержит 8 демонстрационных HR/IT-документов: командировки,
отпуск, адаптация, доступы, VPN, принтеры, оборудование и переговорные.
Это учебные правила, а не регламенты реального работодателя.
В индекс загружаются только файлы из каталога src/knowledge_sources.json.
Техническая документация docs в поисковый корпус не входит.

Для своего GitHub замените URL в документах и каталоге до индексации.
Для реального корпуса также замените указание на учебные правила в промпте.

## Создание индекса

Выполняйте из корня репозитория после настройки yc и окружения:

```bash
source .venv/bin/activate
pip install -r requirements-rag.txt
python scripts/create_search_index.py
set -a
source .env
set +a
```

Скрипт получает текущий folder-id/IAM через yc и использует официальный
CLI yandex-ai-studio vector-stores local. После готовности сохраняет
SEARCH_INDEX_ID в .env, состав корпуса и хеши — в evidence/rag-index.json.
Токен остаётся в окружении дочернего процесса. Повторный запуск с заполненным
SEARCH_INDEX_ID не создаёт дублирующий индекс. Полный деплой — [setup.md](setup.md).

## Проверка

```bash
python scripts/check_rag.py
python scripts/check_rag_context.py
```

Первая команда проверяет известный вопрос про командировку и неизвестную сумму
компенсации. Вторая — свежий поиск printer.md с пустой и текущей историей пользователя.
Проверки не отправляют письма и не создают тикеты; сохраняют настоящие ответы,
поисковые вызовы, найденные файлы и источники в evidence.
Обновление поллера выполняется по [setup.md](setup.md#обновление-существующей-установки).

Почтовые сценарии: вопрос из базы → источник; вопрос вне базы → «не знаю»
и предложение тикета; явное согласие → отдельный тикет. Проверка ссылок и
создания — [qa.md](qa.md), подтверждения — [evidence/README.md](evidence/README.md).
