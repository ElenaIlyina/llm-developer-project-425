## Создание индекса

В обычном терминале компьютера с доступом в интернет:

```bash
cd /home/elian/AI/LLMDev/Project1/llm-developer-project-425
source .venv/bin/activate
pip install -r requirements-rag.txt
python scripts/create_search_index.py
```

Скрипт получает текущий folder-id и IAM-токен через yc. Токен передаётся CLI
через окружение дочернего процесса, не записывается в файлы и не выводится.
Вызывается официальный CLI yandex-ai-studio vector-stores local с --name help-desk-kb
и --format json. После подтверждённой готовности SEARCH_INDEX_ID записывается в .env,
а имена и хеши документов — в docs/evidence/rag-index.json.
Повторный запуск с настроенным SEARCH_INDEX_ID не создаёт дублирующий индекс.
Для поиска уже существующего индекса доступен SDK: AIStudio().search_indexes.list().

## Подключение и проверка

```bash
set -a
source .env
set +a
python scripts/check_rag.py
```

Проверка обращается к реальному Responses API от имени ai-studio-sa,
но не отправляет письма и не запрашивает создание заявок.
Два вопроса: порядок командировки и точная компенсация за скалолазание
(этого правила нет в базе). Сохраняются ответы, queries, найденные файлы,
score и ссылки в docs/evidence/rag-checks.json. Результат вне базы должен
содержать честное отсутствие знаний и предложение тикета без его создания.
Если API не возвращает results/annotations либо порог отсекает нужный документ,
проверка должна выявить это до обновления работающей функции.

После успешной проверки:

```bash
yc serverless trigger pause email-poller-trigger
bash scripts/deploy-email-poller.sh
yc serverless trigger resume email-poller-trigger
```

Если деплой завершается ошибкой, перед возобновлением таймера проверьте,
какая версия активна. Новая версия требует непустой SEARCH_INDEX_ID.

В запросе ровно один file_search, ровно один vector_store_id, максимум 5 результатов.
Начальный RAG_SCORE_THRESHOLD=0.35 — настраиваемый, ещё не откалиброванный порог.
Другой инструмент запроса — существующий MCP ydb-tickets.
Ссылки добавляются кодом из каталога только при совпадении file_citation
и явной строки «Документ: имя-файла.md» в ответе модели.
Неизвестные имена файлов не превращаются в ссылки. В логи не пишутся фрагменты
документов: сохраняются маскированные queries, file_id, filename и score.
Поиск документов и сами ссылки нужно подтвердить на реальном ответе API.
